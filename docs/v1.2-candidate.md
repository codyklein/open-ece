# OpenECE 1.2.0 — exact candidate acceptance

This is a **pending** candidate checklist. Accepted development checkpoints do not
establish acceptance of a newly built unsigned ZIP or a later signed distribution.
Use the final checkpoint report's source commit, CI run, artifact link and inner-ZIP
SHA-256. Do not substitute the published 1.1.0 package or the developer preview.

## Identify and launch

Fedora 44, from a clean checkout at the exact reported commit:

```bash
git rev-parse HEAD
cmake --preset dev
cmake --build --preset dev --target openece -j 4
./build/dev/gui/openece
```

Confirm the printed commit matches the report before building. Do not discard
uncommitted work or switch to a different branch merely to run this checklist.
Record Qt version, desktop/session, scaling, fonts and monitor configuration.

Windows 11: download `OpenECE-v1.2.0-windows-x86_64` from the reported unsigned CI
run. Extract the GitHub artifact wrapper to obtain the inner ZIP, then:

```powershell
Get-FileHash .\OpenECE-v1.2.0-windows-x86_64.zip -Algorithm SHA256
Expand-Archive -LiteralPath .\OpenECE-v1.2.0-windows-x86_64.zip -DestinationPath "$env:USERPROFILE\OpenECE 1.2 RC π test"
& "$env:USERPROFILE\OpenECE 1.2 RC π test\OpenECE-v1.2.0-windows-x86_64\openece.exe"
```

Require exact agreement with the reported inner hash before launch. Use a fresh
extraction, retain all DLLs/plugins/licenses/docs, and use a normal user workflow
without Qt SDK or development PATH entries. If Smart App Control or another policy
blocks the unsigned build, record that restriction and stop that Windows check.
Do not disable SAC, unblock the file, install a private root or bypass protections.
This is not evidence that a future correctly signed distribution will be blocked.

## Bounded smoke on each platform

1. **Startup/About:** launch the actual application, confirm **OpenECE 1.2.0**,
   MIT/notices information and domain navigation. Inspect ordinary focus visibility.
2. **DC:** open `examples/dc-divider.openece` inertly. Tables is selected by default.
   Switch to Schematic, inspect IDs, explicit ground, source polarity and net
   highlighting. Solve DC: supply +10 V, midpoint +5 V, source current −5 mA.
   Switching views must retain results and not add a modified marker.
3. **AC:** open `examples/rc-lowpass.openece`. Inspect Schematic, solve at its stored
   corner, then run/cancel the sweep. Output is across C: about −3.0103 dB / −45°
   in transfer mode, using RMS cosine-reference phasors. View navigation must not
   change probes, excitation, results or sweep lifecycle.
4. **Transient:** open `examples/transient-rc-step.openece`. Inspect Schematic;
   Step pauses after one interval, Run starts fresh, Pause/Resume preserves a run,
   Cancel retains a terminal prefix, Reset results clears derived data. RC output
   approaches 10 V (~9.93 V at 5 ms). Check voltage/current plots and numerical
   trace. Navigate while running/paused, resize the splitter both ways, scroll the
   compressed editor and return to Tables. Nothing should reset or dirty from
   schematic navigation or resize.
5. **Drafts and interaction:** on a disposable circuit, edit names/connections and
   retain raw `1e-` or an empty value. Switch both ways; exact text, IDs and missing
   references must survive. Real edits dirty/invalidate normally. On a clean
   project, Fit, F, +/−, Ctrl+wheel, ordinary wheel, pan and selection must not dirty.
   Zoom far out and back: labels must remain present and become readable again;
   full original text stays available in inspection. Tab/Shift+Tab must enter/leave Fit → Zoom In → Zoom Out → viewport → entities →
   inspector. Inspect plain-text details, not only diagram pixels. Check small
   windows and available scaling/enlarged-text settings; report those actually used.
6. **Persistence:** Save As to a disposable Unicode/space path, reopen and verify
   editable state, Tables defaults and empty results. Import the shipped schema-1
   incomplete project; invalid text survives. Preserve its original with Save As,
   or verify in-place upgrade confirmation. Open/New/Close retain normal
   Save/Discard/Cancel behavior. No FFT, solve, timing, link, sweep or BER starts
   on load. Schematics are not saved as separate drawings.
7. **Existing-domain smoke:** `sine-fft-fir` → Generate (20 Hz passes 40 Hz FIR;
   input edits mark it stale); `half-adder` → truth table; `dff-timing` → Run
   (Q changes at 6/16 ns); `qpsk-link-ber` → noiseless link and one BER Step
   (integer counts). Finish with a clean project and normal exit/relaunch.

Use [example expectations](../examples/README.md) and the [longer schematic review](schematic-workspaces.md)
if a check fails. A nonconnecting crossing must retain a visible gap under net
highlighting. Connectivity layouts intentionally prioritize complete net identity
over textbook placement; do not infer a junction merely from intersecting lines.

## Return evidence and next gate

Record test date, source commit, workflow, inner ZIP/hash (Windows), OS/version,
session/user context, scaling/fonts/monitors, pass/fail/not-tested per item,
policy restrictions and reproducible defects. Do not infer missing details from
earlier tests. True mixed-monitor DPI requires appropriate hardware; otherwise
leave it explicitly unvalidated.

After unsigned-candidate review, signing still requires separate authorization and
the protected environment approval. The exact final signed ZIP needs its own hash,
signature verification and physical Windows 11 acceptance **with SAC enabled**.
No acceptance in this checklist authorizes merge, tag, publication or replacing
historical assets. See [release gates](releasing.md).
